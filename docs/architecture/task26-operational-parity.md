  - `setup` forwards a `docker exec -it` invocation that resolves `WAKE_MAIN_JS` inside the container (same signal the entrypoint script already uses) rather than the host branching on `dev.mode` the way legacy did. The interior `wake sandbox-setup` wizard itself (SSH key generation, interactive gh/claude/codex/cursor auth prompts — legacy `src/cli/sandbox-setup-command.ts`) is a separate top-level CLI command, not a Docker-boundary concern, and is out of this port's scope.
  - `resume` ports only the explicit-args path (`<sessionId> --cwd <path> --cli <claude|codex|cursor>`). Legacy's zero-arg interactive picker over a flat `RunRecord` file has no ported equivalent: target run history lives behind the composition root's event-sourced Execution projection, and building an interactive picker over it is a distinct, larger feature than this Docker-boundary port. Attended resume is also architecturally less central in the target: `RunnerRequest.resumeSessionId` (`src-next/execution/contracts/runner.ts`) already lets the control plane resume a session as part of normal run dispatch, so the manual CLI path is now a debugging aid rather than the primary resume mechanism.
  - `DockerProcess.execute()` now streams `{ stream, text }` chunks to the caller as they arrive instead of resolving once with buffered `stdout`/`stderr`; the real composition (`src-next/bootstrap/surface-cli-applications.ts`) uses `child_process.spawn` instead of `execFile` to produce those chunks incrementally, and `createLoggedDockerCli` writes each chunk through `ProcessLogSink` (still scrubbed) as it arrives.
  - `createContainer()`'s `docker run` now includes `--log-opt max-size=10m --log-opt max-file=3`, matching the legacy adapter's precedent (`src/adapters/docker/docker-cli.ts`, `test/adapters/docker-cli.test.ts`).
  - Interactive exec/UI forwarding (publishing the UI port and ngrok tunnel on `up`/`update`) remains unaddressed — `SandboxDockerOptions` has no `ui`/`tunnel` fields yet.
